Reflection
Fairness does not mean every enrolment request should receive identical treatment. 
Some requests require significantly more CPU processing time or memory resources, while other requests may be affected by class seat limitations. 
Treating all requests exactly the same could result in poor performance and longer waiting times.

The Round Robin scheduling algorithm improves fairness by giving every admitted request a fixed time slice. 
No request is able to monopolise the CPU, and all active requests make progress while waiting their turn.

Modern operating systems use similar approaches when managing competing processes. 
CPU schedulers distribute processor time among processes, while memory management systems determine whether processes can safely execute.

The VU enrolment system follows the same principles by balancing fairness, responsiveness, and correctness while enforcing resource constraints.

Fairness does not necessarily mean treating every request identically. Different processes have different requirements.  Giving every request exactly the same resource allocation would not necessarily be fair or practical. Fairness should mean giving processes a reasonable and non-discriminatory opportunity to progress, rather than giving every process exactly the same outcome.
Round Robin provides a form of procedural fairness by giving each ready process an opportunity to use the CPU. However, other additional factors may need to be considered, such as priority request, type of request or student deadlines.  A priority-based system could process urgent enrolment changes before less urgent requests. So another approach could combine priority scheduling with Round Robin so that requests within the same priority level receive fair CPU access.
Under heavy load, an operating system cannot simply allow every process to run immediately. It must queue processes, allocate resources carefully and prevent resource conflicts. The same principle applies to the VU enrolment system as demonstrated in this assignment.  When demand exceeds available resources, the scheduler must decide who proceeds, who waits and who must be rejected.
The objective is not simply to make every process run immediately. The objective is to maintain a reliable and responsive system while ensuring correctness and making efficient use of limited resources.
